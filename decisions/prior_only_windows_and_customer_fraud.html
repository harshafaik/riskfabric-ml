Feature Engineering Fix: Prior-Only Expanding Windows + Customer Fraud Targeting

What was wrong

Two defects in the ETL feature pipeline at src/etl/features/sequence.rs:

Self-contaminated baselines. hour_deviation_from_norm and amount_deviation_z_score used inclusive expanding windows — the cumulants at row i included row i's own value:

#![allow(unused)]
fn main() {
// Old (line 91-92): current row contaminates its own baseline
let hour_cnt  = col("txn_hour").cum_count(false).over([col("customer_id")]);
let hour_mean = col("txn_hour").cum_sum(false).over([col("customer_id")]) / hour_cnt.clone();
}

For a fraud transaction with a manipulated amount, the mean includes that manipulated amount. The deviation is artificially small — the baseline is inflated by the very anomaly it should detect. Over time, as more fraud accumulates in a customer's expanding window, the baseline drifts further from the true customer-normal.

The scorer (scorer.py) was already clean — Welford's algorithm reads prior state, computes the z-score, then updates state. The leakage was ETL-only, contaminating training data but not the inference path.

Customer fraud targeting was not wired. CustomerBase.is_fraud is populated (2% of customers, customer_gen.rs:81) but never read by determine_targeting(). Every transaction was an independent Bernoulli trial against the global 1% base rate — fraud had no customer-level cluster structure. In production, compromised accounts and serial fraudsters exist; this generator treated them identically to ordinary customers.

The fix

Prior-only windows (sequence.rs:89-118). All cumulants are shifted by one row:

#![allow(unused)]
fn main() {
let hour_cnt_prev  = col("txn_hour").cum_count(false).over([col("customer_id")]).shift(lit(1));
let hour_sum_prev  = col("txn_hour").cum_sum(false).over([col("customer_id")]).shift(lit(1));
let cnt_prev = col("amount").cum_count(false).over([col("customer_id")]).shift(lit(1));
}

First transaction defaults to zero. is_finite() guard replaces the old fill_nan to handle edge cases where 0.0 / 0.0 produces infinity. Both features also get the guard to prevent XGBoost QuantileDMatrix crashes on inf values.

Customer fraud multiplier (transaction_gen.rs:170-174). Fraud-prone customers target at 3× the base rate (configurable via fraud_injector.customer_fraud_multiplier in fraud_rules.yaml). The effective share is computed per-transaction:

#![allow(unused)]
fn main() {
let effective_share = if customer.financial.is_fraud {
    config.rules.fraud_injector.target_share * config.rules.fraud_injector.customer_fraud_multiplier
} else {
    config.rules.fraud_injector.target_share
};
}

The model never sees customer identity — behavioral features transmit the signal.

Quantified impact

Three isolated runs, same seed (5555), same customer count (3400), same chronologically-split test set (last 20%). Only the variable of interest changes between runs.

RunAUCDescription
A0.7622Old ETL (self-contaminated baselines), no customer wiring
B0.7707Fixed ETL (prior-only windows), multiplier=1.0
C0.7827Fixed ETL (prior-only windows), multiplier=3.0

ETL fix alone (B − A): +0.85 AUC points

FeatureRun ARun BΔ
hour_deviation_from_norm3.2%8.2%+5.0pp
transaction_channel18.0%14.3%−3.7pp
amount_deviation_z_score17.3%15.4%−1.9pp

hour_deviation_from_norm nearly triples in importance. The old inclusive window was systematically dampening the signal: a fraud transaction's manipulated timestamp was being compared against a mean that already included that manipulation. Removing self-contamination redistributes weight from channel/amount to the unmuted hour feature.

Customer wiring (C − B): +1.20 AUC points

FeatureRun BRun CΔ
rapid_fire_transaction_flag3.6%1.1%−2.5pp
time_since_last_transaction10.9%12.8%+1.9pp
transaction_channel14.3%16.2%+1.9pp

When fraud clusters around specific customers, those customers generate bursts naturally as part of their normal spending pattern — rapid-fire stops discriminating between fraud and legitimate. The model shifts to channel-based signal (fraud-prone customers don't change their payment channel every transaction) and inter-transaction timing (clustered fraud produces systematically different spacing than uniform fraud).

Leakage check

The wiring has no path back to customer identity. The feature list is purely behavioral. Same seed → same distributions → identical AUC. The 1.20pp gain flows through observable behavioral patterns, not through the customer ID that generated them.
